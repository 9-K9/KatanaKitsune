HOW TO CHECK THE PROJECT
-------------------------------------------------------------------------------

From the repo root:

    tools/check-connections.sh          # stale signal wiring — see below
    godot --headless --editor --quit    # import pass
    godot --headless                    # run the game headless

Three things that will mislead you:

  1. RUN THE IMPORT PASS TWICE after adding a script with a `class_name`. The
     first populates the global class registry; the second is the real verdict.
     A new class reports "not declared in the current scope" until then.

  2. `godot --headless --check-only --script res://foo.gd` DOES NOT LOAD
     AUTOLOADS OR THE CLASS REGISTRY. Any script touching Roster, CheatManager,
     Dialogic or another `class_name` will report "Compilation failed" there
     while being perfectly fine. Only the editor import pass is authoritative.
     This wasted time twice.

  3. tools/check-connections.sh catches what nothing else does. A .tscn wires
     signals by full node path; reparent or rename a node and the path stops
     resolving, and GODOT SAYS NOTHING — no error, no warning, a clean headless
     run. The scene renders, the button highlights on hover, clicking does
     nothing. Run it after ANY change to a scene's node tree. Exits non-zero,
     so it works as a pre-commit gate.

ARCHIVE POLICY
  archive/ holds code that is no longer reachable but is kept rather than
  deleted. A .gdignore makes Godot skip the directory entirely — scripts are
  not parsed, class_name is not registered. Verified: Godot never reads it.
  Moving a file out is all it takes to restore.

  archive/README.md         what was archived, why, and what replaced it
  archive/removed-members.md functions and fields deleted out of still-live
                            files, reproduced verbatim so they can be restored

  NOTE: the Desktop's own sweep (c88eb7c0) DELETED rather than archived. That
  is recoverable from git at c88eb7c0^ but is not in archive/.

TOOLING
  tools/check-connections.sh + tools/check_scene_connections.gd
    Finds stale [connection] paths, missing handler methods, and buttons with
    no live handler. The wrapper locates Godot itself ($GODOT, then PATH, then
    searches $HOME), so `godot` need not be installed.
    Validated by breaking things deliberately — a checker that has only ever
    passed proves nothing.

  scripts/system/IsoFacing.gd
    The one eight-way facing table. The reverse map is derived from the
    forward one so the two directions cannot drift apart.

  scripts/stateMachine/class/OneShotAttackState.gd
    Shared body for committed single-clip attacks.

ENEMY TAUNTS

(A) DONE 2026-10-03 — the kicks no longer overrun their art
    highKick, roundKick and katanaKick locked input for 0.75s over 0.67s of

  2026-10-13  online-multiplayer foundation (commit d53c363a, pushed)
===============================================================================

ASKED: what would it take to put the game on web with online co-op for up to
4 players, and could an AI no-code tool (Lovable) build the hosting side.
ANSWERED: no — Lovable/Bolt/etc. can scaffold a peripheral lobby webpage at
best; they cannot export Godot to WASM, write the GDScript netcode, or run
the stateful authoritative game server. User chose: dedicated server (not
peer-to-peer), simple room code to join (no accounts, no lobby website).

WHAT LANDED — foundation only, zero gameplay wiring, zero existing
gameplay/combat/state-machine files touched:

  scripts/system/NetworkManager.gd (new autoload)
    Wraps WebSocketMultiplayerPeer (works from a browser export too — raw
    ENet/UDP does not). host(port) / join(address, port) /
    join_room_code("host[:port]"). `--server` or `--server=PORT` on the
    command line boots straight into a headless dedicated server instead of
    the title screen — that's the process meant to run on a small always-on
    VPS/PaaS box.

  scripts/system/PlayerInput.gd
    Added a third device sentinel, NETWORK, next to the existing
    KEYBOARD/BOT.

  scripts/system/NetworkInput.gd (new)
    A PlayerInput for a network-controlled slot, shaped exactly like
    BotInput — never reads Input.* locally. NetworkManager now feeds it
    validated snapshots from that peer's client.

  scripts/system/Roster.gd
    join_network(peer_id) seats a connecting peer, reusing a slot already
    held open for a dropped network player rather than always growing the
    roster (a fresh WebSocket connection always gets a new peer id, so "the
    same peer reconnecting" has to be matched by slot, not id). drop_peer()
    marks that slot lost, reusing the EXACT device_lost/device_regained
    signals and pause behaviour already built for a pulled gamepad — a
    dropped network player already halts the party and waits, for free.
    input_for() returns NetworkInput for a network slot.

  tools/validate_networking.gd / .tscn / .sh (new)
    A real two-process headless check: hosts on loopback, connects a second
    process as a client, confirms the peer gets a roster slot, confirms
    input reaches the server-side NetworkInput, then confirms disconnect
    marks it lost and clears held input.
    At the time this foundation landed, the two-process test had never
    completed: running both Godot processes crashed the sandbox from memory
    pressure. That warning is historical now: the expanded networking check
    passed on 2026-10-13, including bounded input delivery and disconnect
    clearing.

        tools/validate_networking.sh

    Prints PASS/FAIL per check, exits nonzero on any failure or timeout.
    FIX WHATEVER IT REPORTS BEFORE BUILDING ANYTHING ON TOP OF THIS.

  NETWORKING.md (new)
    The fuller technical status doc — what's done, what deliberately is not,
    why the scope stopped where it did, how to actually run the dedicated
    server.

  1. Gate the "decide and simulate" half of AnimatedCharacterClass /

     the server ever runs real movement/AI/damage logic; add a
     MultiplayerSynchronizer to the player and enemy scenes to replicate

  5. Client-side prediction/interpolation, web export bundle-size tuning,
