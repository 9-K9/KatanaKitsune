HOW TO CHECK THE PROJECT
-------------------------------------------------------------------------------

From the repo root:

    tools/check-connections.sh          # stale signal wiring — see below
    godot --headless --editor --quit    # import pass
    godot --headless                    # run the game headless

Three things that will mislead you:

  1. RUN THE IMPORT PASS TWICE after adding a script with a `class_name`. The
     first populates the global class registry; the second is the real verdict.
     A new class reports "not declared in the current scope" until then.

  2. `godot --headless --check-only --script res://foo.gd` DOES NOT LOAD
     AUTOLOADS OR THE CLASS REGISTRY. Any script touching Roster, CheatManager,
     Dialogic or another `class_name` will report "Compilation failed" there
     while being perfectly fine. Only the editor import pass is authoritative.
     This wasted time twice.

  3. tools/check-connections.sh catches what nothing else does. A .tscn wires
     signals by full node path; reparent or rename a node and the path stops
     resolving, and GODOT SAYS NOTHING — no error, no warning, a clean headless
     run. The scene renders, the button highlights on hover, clicking does
     nothing. Run it after ANY change to a scene's node tree. Exits non-zero,
     so it works as a pre-commit gate.

1. WHAT EXISTS NOW
-------------------------------------------------------------------------------

ARCHIVE POLICY
  archive/ holds code that is no longer reachable but is kept rather than
  deleted. A .gdignore makes Godot skip the directory entirely — scripts are
  not parsed, class_name is not registered. Verified: Godot never reads it.
  Moving a file out is all it takes to restore.

  archive/README.md         what was archived, why, and what replaced it
  archive/removed-members.md functions and fields deleted out of still-live
                            files, reproduced verbatim so they can be restored

  NOTE: the Desktop's own sweep (c88eb7c0) DELETED rather than archived. That
  is recoverable from git at c88eb7c0^ but is not in archive/.

TOOLING
  tools/check-connections.sh + tools/check_scene_connections.gd
    Finds stale [connection] paths, missing handler methods, and buttons with
    no live handler. The wrapper locates Godot itself ($GODOT, then PATH, then
    searches $HOME), so `godot` need not be installed.
    Validated by breaking things deliberately — a checker that has only ever
    passed proves nothing.

  scripts/system/IsoFacing.gd
    The one eight-way facing table. The reverse map is derived from the
    forward one so the two directions cannot drift apart.

  scripts/stateMachine/class/OneShotAttackState.gd
    Shared body for committed single-clip attacks.

ENEMY TAUNTS
  alert -> provoke -> taunt -> hunt, with TauntComponent holding the timeline
  and the spoken/speaking latches. Lines in dialogue/enemies/.
  THE TRIGGER MOVED: the original input hook was removed by the multiplayer
  rewrite; provoke() now fires from seductiveDance.gd. The feature survived,
  rewired.

4. WHAT NEEDS CONTINUING
-------------------------------------------------------------------------------

(A) DONE 2026-10-03 — the kicks no longer overrun their art
    highKick, roundKick and katanaKick locked input for 0.75s over 0.67s of
    animation. All five one-shot attacks now measure the lock from the
    SpriteFrames instead of carrying a number, so a redrawn clip changes the
    lock with it. midKick and katanaSlashCrouched were already exact and are
    unchanged; the three kicks each lost 0.08s.
    A missing clip measures 0, which would end an attack on the frame it began,
    so OneShotAttackState falls back to 0.75s in that case.

(B) DONE 2026-10-03 — stateAnimation's dead fps argument is gone
    It set `fps = null` on its first line while nineteen call sites passed a
    number. Measured before deciding: thirteen of the nineteen disagreed with
    the rate the SpriteFrames is authored at, and not slightly — idle passed 1
    against 5, walk 2 against 8, fastRun 3 against 16. Honouring the argument
    would have played most of the game in slow motion, so it was removed rather
    than made to work. The art carries its own rate.
    The `fps` field on OneShotAttackState went with it.

    NOTED IN PASSING, NOT INVESTIGATED: setting AnimatedSprite2D.animation from
    a state does not stick in a headless frame — the AnimationTree appears to
    overwrite it. Verified this is pre-existing (identical before and after the
    change), so it is not fallout, but stateAnimation may be doing less than it

-------------------------------------------------------------------------------

  - enemyIdle.gd is NOT superseded by `alert`. `idle` is the unaware/roaming
    state, `alert` the lost-sight search state; enemyAlert.gd transitions INTO
    idle, and both monster scenes start on it. It was nearly archived on that
    wrong assumption.

  - The _find_player() multiplayer bug IS FIXED. Radar, DebugShapes, WallFade
    and PillarFade all use Roster now. The 2026-10-02 log listed it as the
    highest-value outstanding item; the Desktop closed it.

  - The stateDirection() halves no longer disagree on bad input. They did when
    first surveyed; the player's had since been converted to a dict. The
    IsoFacing work removed the second copy, not the disagreement.

  - glow.tres was never part of the chair/table y-sort work — that diff is a
    uid stamp from a headless editor run. The y-sort fixes came in with the
    pull (cc97de7c, f25c6559, 66a01bc1, c33ffc88).

  - The corner enemy placement in ysortmap.tscn and the Room.corners() work in
    GeneratedLevel/LevelGenerator were both inside subsystems that are now
    deleted. The old question "are the corner enemies standing in a wall" is
    moot; those scenes no longer exist.
